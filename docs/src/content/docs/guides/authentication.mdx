Most applications require some form of authentication, and a poorly designed approach can lead to significant issues. This starter kit provides a solid foundation for implementing authentication in your application using Supabase, including support for soft login (anonymous guest access), account linking, and secure token storage.

We use [Zustand](https://github.com/pmndrs/zustand) to globally manage the application's authentication state, mirroring the Supabase session status in real-time.

## Authentication Store

The authentication store, located at `src/lib/auth/index.tsx`, is the central hub for managing the app's authentication state. It listens to Supabase's `onAuthStateChange` event, ensuring that your UI is always in sync with the backend.

<CodeBlock file="src/lib/auth/index.tsx" />

The store is composed of the following states and actions:

-   **States**:
    -   `session`: The user's session object from Supabase.
    -   `user`: The user object from Supabase.
    -   `status`: The authentication status (`idle`, `signIn`, `signOut`).
    -   `isAnonymous`: A boolean flag indicating if the current user is a guest (anonymous).

-   **Actions**:
    -   `signIn`: (Deprecated for direct use) Internal action to update state.
    -   `signOut`: Signs out the user from Supabase and resets the app state (including the "First Time" flag), effectively redirecting them to the onboarding flow.
    -   `hydrate`: Initializes the auth state. If no session exists, it automatically creates an anonymous session (Soft Login).

## Secure Storage

We use `expo-secure-store` via a custom adapter (`src/lib/auth/secure-storage.ts`) to persist Supabase sessions securely. This is critical for security, as standard `AsyncStorage` or `MMKV` are not encrypted.

```typescript
// src/lib/auth/secure-storage.ts
import * as SecureStore from 'expo-secure-store';

export const SupabaseStorage = {
  getItem: (key: string) => {
    return SecureStore.getItemAsync(key);
  },
  setItem: (key: string, value: string) => {
    SecureStore.setItemAsync(key, value);
  },
  removeItem: (key: string) => {
    SecureStore.deleteItemAsync(key);
  },
};
```

## Soft Login (Anonymous Auth)

The app is designed with a "Soft Login" flow. When a user first opens the app, they are automatically signed in as an anonymous user. This allows them to explore the app and create content (like Todos) without immediately hitting a registration wall.

-   **Flow**:
    1.  App launches.
    2.  `hydrateAuth` checks for a session.
    3.  If none, calls `supabase.auth.signInAnonymously()`.
    4.  User is logged in as a guest (`isAnonymous: true`).

## Guest Conversion (Account Linking)

When a guest user decides to sign up (e.g., to sync their data or access premium features), we **convert** their anonymous account to a registered account. This preserves their `user_id` and all associated data (like Todos).

We handle this in `src/api/auth/use-sign-up.ts`:

```typescript
const signUpOrUpdate = async (variables: Variables): Promise<void> => {
  const { user: currentUser } = useAuth.getState();
  const isAnonymous = currentUser?.is_anonymous;

  if (isAnonymous) {
    // Convert Guest -> Registered User
    await supabase.auth.updateUser({
      email: variables.email,
      password: variables.password,
      data: { name: variables.name },
    });
  } else {
    // Standard Sign Up
    await supabase.auth.signUp({
      email: variables.email,
      password: variables.password,
      // ...
    });
  }
};
```

## Guarding Routes

We use `expo-router` for navigation. The root layout (`src/app/_layout.tsx`) handles global modals (like Sign In/Sign Up), while the app logic (`src/app/(app)/_layout.tsx`) allows access to all routes for both Guests and Registered users.

Specific actions (like "Delete Account") are conditionally hidden or disabled for Guest users in the UI.

## Deleting a User Account

To allow users to delete their own accounts, you need to create a custom RPC function in Supabase.

1.  **Create the function** in Supabase SQL Editor:

    ```sql
    create or replace function public.delete_user()
    returns void
    language sql
    security definer
    as $$
      delete from auth.users where id = auth.uid();
    $$;
    ```

2.  **Grant permission**:

    ```sql
    grant execute on function public.delete_user() to authenticated;
    ```

The `useDeleteUser` hook (`src/api/auth/use-delete-user.ts`) calls this function. When a user deletes their account, we also reset the local "First Time" state (`IS_FIRST_TIME`), redirecting them back to the onboarding screens.

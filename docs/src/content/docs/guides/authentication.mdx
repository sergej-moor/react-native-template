Most applications require some form of authentication, and a poorly designed approach can lead to significant issues. This starter kit provides a solid foundation for implementing authentication in your application using Supabase.

We use [Zustand](https://github.com/pmndrs/zustand) to globally manage the application's authentication state. Zustand is a simple, high-performance state management library that integrates seamlessly with React. It offers advantages over the standard Context API, such as selectors to prevent unnecessary re-renders and the flexibility to be used outside of the React component tree.

## Authentication Store

The authentication store, located at `src/lib/auth/index.tsx`, is the central hub for managing the app's authentication state.

<CodeBlock file="src/lib/auth/index.tsx" />

The store is composed of the following states and actions:

-   **States**:
    -   `session`: The user's session object from Supabase.
    -   `user`: The user object from Supabase.
    -   `status`: The authentication status, which can be:
        -   `idle`: The initial state before authentication status has been determined.
        -   `signIn`: The user is authenticated.
        -   `signOut`: The user is not authenticated.

-   **Actions**:
    -   `signIn`: A function to sign in the user. It takes the `session` and `user` objects, persists them to storage, and updates the state.
    -   `signOut`: An action to sign out the user. It clears the session from Supabase, removes the data from storage, and updates the state.
    -   `hydrate`: An action that runs on app startup to check for a persisted session in storage. It updates the state to `signIn` if a valid session is found, or `signOut` otherwise.

The store also automatically listens to Supabase's `onAuthStateChange` event, allowing it to respond to authentication changes in real-time from any part of the application, such as token refreshes or user updates.

## Using the Authentication Store

To use the store, import it from `@/lib`. You can then access the state or call actions from any component or even from outside the React tree.

```tsx
import { useAuth, hydrateAuth } from '@/lib';

// Call this on app startup to restore the session
hydrateAuth();

const MyComponent = () => {
  const status = useAuth.use.status();
  const user = useAuth.use.user();
  const signOut = useAuth.use.signOut();

  return (
    <View>
      <Text>Status: {status}</Text>
      {user && <Text>Welcome, {user.email}</Text>}
      <Button title="Sign Out" onPress={signOut} />
    </View>
  );
};
```

## Guarding Routes

A common use case is to protect certain parts of your application based on the user's authentication status. With our setup, you can easily guard your routes.

The root layout file, `src/app/_layout.tsx`, is a great example of how to implement route protection. It checks the authentication `status` from the store and renders the appropriate navigator—either the main app navigator for authenticated users or the sign-in navigator for unauthenticated users.

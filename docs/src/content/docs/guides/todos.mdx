This guide explains the architecture and implementation of a professional, production-ready todo app that works **Offline-First** using Supabase as the backend. It features Optimistic Updates for instant UI feedback and background synchronization when connectivity is restored.

## Overview

The todo app demonstrates:

- **Cloud-First Architecture**: Data is stored in Supabase (PostgreSQL).
- **Offline Capabilities**: Uses `networkMode: 'offlineFirst'` and `@react-native-community/netinfo` to queue offline mutations.
- **Optimistic Updates**: Immediate UI feedback (Fake ID -> Real ID).
- **Modern UX**: Swipe-to-delete, multi-step onboarding, and soft login.
- **Type Safety**: Shared types between Frontend and Supabase DB.

## Database Schema (Supabase)

The app expects a `todos` table in Supabase:

```sql
CREATE TABLE todos (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  description TEXT,
  completed BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ -- For soft deletes
);

-- Enable RLS
ALTER TABLE todos ENABLE ROW LEVEL SECURITY;

-- Policies
CREATE POLICY "Users can manage their own todos" ON todos
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

## Offline Strategy & Optimistic Updates

We use **React Query (TanStack Query)** to handle data fetching and synchronization.

### 1. Network Configuration (`src/api/common/api-provider.tsx`)

We configure the `QueryClient` to handle offline states intelligently:

- **Queries (`offlineFirst`)**: If offline, read from the cache. If no cache, try to fetch.
- **Mutations (`online`)**: Standard mode. If offline, React Query pauses the mutation and puts it in a queue. It waits until `NetInfo` reports a connection before executing.
- **Optimistic UI**: Even though the mutation is paused, `onMutate` runs immediately, so the user sees the change instantly.

### 2. Optimistic Create Example

When a user creates a todo:

1.  **UI Update**: We immediately inject a "fake" todo with a temporary ID into the React Query cache.
2.  **Network Request**:
    - **If Online**: The request goes to Supabase. On success, we invalidate the cache to get the real ID.
    - **If Offline**: The request is paused. The fake todo stays visible. When online, it sends.

```typescript
// src/api/todos/use-create-todo.ts
export const useCreateTodo = createMutation<Todo, CreateTodoInput>({
  mutationFn: async (input) => {
    // 1. Real Network Request (Paused if offline)
    const { data, error } = await supabase.from('todos').insert(...).select().single();
    if (error) throw error;
    return mapToTodo(data);
  },
  onMutate: async (input) => {
    // 2. Cancel outgoing refetches
    await queryClient.cancelQueries({ queryKey: ['todos'] });

    // 3. Snapshot previous state
    const previousTodos = queryClient.getQueryData<Array<Todo>>(['todos']);

    // 4. Optimistic Update (Fake ID)
    const optimisticTodo: Todo = {
      id: generateTodoId(), // Temporary ID
      title: input.title,
      completed: false,
      // ...
    };

    queryClient.setQueryData(['todos'], (old) => [optimisticTodo, ...(old ?? [])]);

    return { previousTodos };
  },
  onError: (err, variables, context) => {
    // 5. Rollback on error
    if (context?.previousTodos) {
      queryClient.setQueryData(['todos'], context.previousTodos);
    }
  },
  onSettled: () => {
    // 6. Sync with server (get real ID)
    queryClient.invalidateQueries({ queryKey: ['todos'] });
  },
});
```

## Guest Users & Data Sync

Since we use **Anonymous Auth** (Soft Login):

1.  **Guest**: The `user_id` in the `todos` table corresponds to the anonymous user ID.
2.  **Sign Up**: When the user converts to a registered account (`updateUser`), the `user_id` remains the same.
3.  **Result**: The user keeps their todos seamlessly after signing up.

## Soft Deletes

We use "Soft Deletes" (`deleted_at` column) instead of hard `DELETE` SQL commands. This allows for easier undo functionality and conflict resolution in the future.

```typescript
// src/api/todos/use-delete-todo.ts
mutationFn: async (input) => {
  await supabase.from('todos').update({ deleted_at: new Date().toISOString() }).eq('id', input.id);
};
```

The `useTodos` query filters these out:

```typescript
// src/api/todos/use-todos.ts
.select('*')
.is('deleted_at', null)
```
